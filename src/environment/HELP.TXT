.topic abzxtools
  ษอออออออออออออออออออออออออออออออป
  บ WARAJEVO ZX SPECTRUM EMULATOR บ
  ศอออออออออออออออออออออออออออออออผ

Warajevo is ZX Spectrum emulator with very high compatibility with existing
Spectrum software. It was written in Bosnia and Herzegovina by Zeljko Juric and Samir
Ribic during and after the Bosnian war.

You are now in the environment of Warajevo emulator.

Warajevo emulator can deal with {tape files:Tapefiles},
{snapshot files:Snapfiles}, {microdrive cartridge files:Cartfiles} and
Timex {DOCK extension files:dockfiles}.

On the topmost line of the environment screen there is a {main menu:moptions}.
You can access it using one of the following ways:

- Press Ctrl+F10, then use cursor keys to move through menu;

- Press Alt with a first letter of the menu;

- Move the mouse pointer to the menu name and then click the left button.

The bottommost line of the screen contains a (incomplete) list of
{shortcut keys:hotkeys}. You can also select them using the mouse. Decimal
number in the corner is the amount of free RAM.

In the bottom left corner of the screen, there is the {start button:sbutton}.

In the middle of the screen there is a {window} with current file names and
current parameter settings. If you work with the environment in graphic mode,
a window with current content of emulated screen is also shown. Double click on
this window will {run emulator:runemul}.

.topic Tapefiles
  ษออออออออออออออออออออออป
  บ TAPE EMULATION FILES บ
  ศออออออออออออออออออออออผ

Tape files are files used for emulation of Spectrum tapes. They are organized
as sequence of {blocks} linked into one list. Tape files have the extension
'.TAP'. You may use also tape files which uses emulator 'Z80' by Gerton Lunter.
Their format is quite different compared with the native format which Warajevo
emulator uses, but Warajevo can work with them.

  ศออออออออออออออออผ

Snapshot files are files that contain Spectrum's memory image, including
registers and some hardware ports. They have extension '.Z80'.

.topic dialog
  ษอออออออออป
  บ DIALOGS บ
  ศอออออออออผ

Dialogs are special forms of {windows:window}. When you work with dialog, you
can not access to options from the {main menu:moptions}.

The dialog window usually has many items such as {list boxes:listbox}, the
{OK button:OKbutton}, {Cancel buttons:Cancelbutton}, {input lines:inputline},
{radio buttons:radiobutton}, {checkboxes:chkbox}, static text etc.

One of the items is focused and it is active. You can move through items using
Tab and Shift+Tab keys.

If you have the mouse, you can directly access the items by moving the mouse
pointer to the desired item and then by pressing the mouse button.

If the item has highlighted the first letter, you can press Alt with this
letter to reach it.

Selecting the OK button will usually start the desired operation. Selecting of
the Cancel button or pressing Esc will cancel changes and return us to the
{main menu:moptions}.

.topic tparameters
 ษอออออออออออออออออป
 บ TAPE PARAMETERS บ
 ศอออออออออออออออออผ

Tape parameters option in {Tapes:ttapes} submenu of {TapeFiles:tfiles} menu
allows setting various parameters assigned to the selected
{tape file:TapeFiles}.

This option opens {dialog} with {file selecting dialog:fsdialog} called Tape
position, {radio buttons:radiobutton} called Loading method, some
{checkboxes:chkbox}, {input lines:inputline}, {OK button:okbutton}, and
{Cancel button:cancelbutton}.

Tape position dialog allows selecting of active {block:blocks} in a
{tape file:TapeFIles}. This block will be active after entering emulator.

Loading method radio buttons selects {tape emulation algorithm:talgs}.

Checkbox 'Stop mode' determines would the emulator stop after every loaded
block.

Checkbox 'Hide border' is obsolete in release 2.5. (it is still present due to
compatibility).

Checkbox 'Autostart' determines would the emulator automaticaly load and run
selected file. If you select autostart, this will {unselect:sunselect} current
{snapshot file:snapfiles} because automatic loading from tape is uncompatibile
with snapshots.

Input line 'Initial attribute' determines initial color attribute when you
using auto start.

Parameters from this dialog will be ignored if MIC/EAR device selected in
{Sound setting:sound} dialog is not "Tape file".

.topic copynew
 ษอออออออออออออป
 บ COPY TO NEW บ
 ศอออออออออออออผ

This option copies the selected {blocks} of one {tape file:TapeFIles} to
another.

After you select the destination file using {file selecting dialog:fsdialog}
you will see on the screen new {dialog}.

The top {list box:listbox} lists the {blocks} of source tape. You can select or
unselect the blocks using Space, Enter or by double clicking the mouse. The
selected block will be signed with ''.

The bottom list box lists the blocks of the destination tape file. All selected
blocks from the source tape file will be stored before the highlighted block in
the destination tape file (or appended to end of the file if you highlight EOF
marker). If the destination tape is in {Lunter's format:Tapefiles}, copying is
possible only on the end of the tape.

You can start coping using the {OK button:OKbutton} or ignore it using the
{Cancel button:Cancelbutton}.

.topic reorder
 ษอออออออออป
 บ REORDER บ
 ศอออออออออผ

This option rewrites all {blocks} of the {tape file:TapeFiles} to the new tape
file, but in new order.

The {dialog} for defining new order contains the {list box:listbox},
{OK button:OKbutton} and {Cancel button:Cancelbutton}.

The list box for this option is very specific. When you select the block using
Enter, Space or double clicking the mouse, any further moving of the highlight
through the list box will move the block too. Pressing the Enter key again will
park the block to the new location and then you can move next block using the
same method.

When you define the new order, you can select the OK button. This will create
backup (BAK) file and new tape (TAP) file. You must have enough space on disk
for the backup file. If you have no, use {Change position:chgpos} option
instead.

.topic extract
 ษอออออออออป
 บ EXTRACT บ
 ศอออออออออผ

This option extracts the selected {blocks} to standalone files.

The {dialog} for selecting blocks to be extracted contains the
{list box:listbox}, group of {radio buttons:radiobutton}, the
{OK button:OKbutton} and the {Cancel button:Cancelbutton}.

In the list box the you can select/unselect the blocks to be extracted using
Space, Enter or double clicking the mouse. The selected block will be signed
with ''.

The radio buttons determine treating of the {flag byte:flagbyte}. It can be the
first byte in extracted file or file extension. If you want to ignore (throw
away) the flag byte, the second option is recommended.

The file names of extracted blocks will be derived from their position and name
of the {tape file:TapeFiles}. All {compressed:implode} blocks will be
decompressed in the extracted version.

.topic exclude
 ษอออออออออป
 บ EXCLUDE บ
 ศอออออออออผ

This option excludes {block:blocks} from the chain in the
{tape file:TapeFiles}.

The {dialog} for selecting the block which will be excluded contains the
{list box:listbox}, the {OK button:OKbutton} and the
{Cancel button:Cancelbutton}.

Unlike option {Delete}, this option only tells to pointers in the tape file to
forget that this block exists, but it still occupies the space in the file. Use
this option only you have no enough space on disk for the backup file, or if
option {Delete} will take too much time. Later, excluded blocks can be
psyhically removed using {Linearize:linonly} option in {Implode} menu, submenu
{Compress}.

This option works only with tapes in native {Warajevo format:tapefiles}, not
with tapes in {Lunter's format:tapefiles}.

The selecting of the OK button will exclude the highlighted block from the
chain.

.topic chgpos
 ษอออออออออออออออออป
 บ CHANGE POSITION บ
 ศอออออออออออออออออผ

Changes position of one {block:blocks} in the {tape file:TapeFIles}.

The {dialog} for selecting block which position will be changed contains the

The selecting of the OK button will update the look of the chain.

.topic implode
 ษอออออออออออออออออป
 บ IMPLODE SUBMENU บ
 ศอออออออออออออออออผ

Every {block:blocks} on {tape file:TapeFIles}, except {headers:header}, can be
compressed. The compression reduces the occupied space on the disk for about
30-60% or even more.

Imploding is feature which is exclusive characteristic of native
{Warajevo format:tapefiles}, so options from this menu will not work when
active tape is in {Lunter TAP format:tapefiles}.

This submenu contains options for {compressing:compress},
{decompressing:decomp} and informing us about {efficiency:eff} of the
compression.

 ศออออออออออออออออออผ

{whole tape file:compall}, only {selected blocks:compsel} or
{linearizing:linonly} the {tape file:TapeFIles}.

{Warajevo emulator:abzxtools} uses the Imploding algorithm, similarly as most
of archivers (like ZIP and ARJ).

.topic compall
 ษออออออออออออออป
 บ COMPRESS ALL บ
 ศออออออออออออออผ

This option will {compress:implode} all {blocks} in the {tape file:TapeFiles}
except {headers:header}, already {compressed:implode} blocks and blocks where
the compression will give worse result.

.topic casssample
 ษอออออออออออออออออออออป
 บ SAMPLE FROM CASSETE บ
 ศอออออออออออออออออออออผ

Samples tone record from real Spectrum tapes, convert them into
{EAR Sample:earsample} blocks and appends such {blocks} to the end of
current Warajevo {tape file:TapeFIles}. This option is dedicated for

Checkbox 'Loading sound' determines would the program produce sound during
sampling from cassette.

Sampling from tape needs allocation of huge memory buffers and linear
addressing of the memory, so 386+ processor with at least 2 Mb of memory is
required. Input fields 'Lowest linear address' and 'Highest linear address'
contains start and end address of allocated sampling buffer. You may change
these values on your own responsibility. Decreasing of start address below
1114112 are extremely risky. Increasing of end address is usable for sampling
of very long blocks or during sampling on frequency 44100 Hz. For more
information, see the manual.

TO PREVENT EVENTUAL CONFLICT WITH DRIVERS WHICH CAN ACCESS MEMORY ABOVE 1 MB +
64 KB, REMOVE ANY SUCH DRIVERS LIKE QEMM, EMM386, RAMDRIVE, VDISK, SMARTDRV,
HIMEM, MS WINDOWS ETC. BEFORE USING THIS OPTION!!!

When you select OK button, sampling will start. Since the program does not
perform any kind of checking of nature of sampled data, no loading errors will
be noticed using this option. Eventual wrong loading will cause loading error
only when you try to load a program from created TAP file. The sampling will
be interrupted when you press on ESC key. After transferring, it is not bad
idea to exit the environment and reboot the computer.

.topic tzxwara
 ษอออออออออออออออออป
 บ TZX TO WARAJEVO บ
 ศอออออออออออออออออผ

TZX format is tape format by Tomaz Kac from Slovenia, which is planed to be an
universal format for keeping Spectrum programs on such way that it includes
all possible cases which appears on real Spectrum.

This format may include textual program descriptions, pictures, and even some
commands (some kind of macrolanguage). In this moment, this format is supported
in X128 emulator by James McKay and in MultiMachine emulator by Paul Hodgson
(both from Great Britain).

When you select this option, on the screen you will see
{file selecting dialog:fsdialog} for defining name of TZX tape file.

All {blocks} from 'TZX' tape file will be appended to current
{Warajevo tape file:tapefiles}. TZX format is much more complex than TAP
format, so many details during conversion will be simply ignored. Also, rules
of TZX conversion may be customized using option
{TZX conversion setup:tzxsetup}

The rules of the conversion are:

'Standard speed' blocks will be sampled to {EAR sample:earsample} blocks, or
converted into {headerless} blocks (if you thrust in EDGE RECOGNIZER),
depending of current {settings:tzxsetup}. For more details about edge
recognizer, see the manual. Pause after them will be sampled to EAR sample
block or ignored, depending of settings.

'Pure tone' and 'Sequence of pulses' blocks will be sampled to EAR Sample
blocks or ignored, depending of settings.

'Turbo loading' and 'Pure data' blocks will be converted to EAR Sample blocks,
or into headerless blocks (if you believe that edge recognizer would
recognize them), depending of settings.

'Direct recording' blocks will be converted only if they follows recommended
sampling frequencies 44100 or 22050 Hz. Optionally, they also may be ignored.
                                        
'Finite Pause' block will be sampled to EAR sample block.

'Infinite pause' block will be saved as normal block, with zero size.

'Group Start' block indicates that following EAR samples should not be
separated.

'Group End' block starts separating of following samples.

'Loop' and 'EndLoop' blocks are implemented using repeated sampling.

'Jump To' block is implemented only for forward jumps; backward jumps may
optionally be ignored.

'Call Sequence' and 'Return From Sequence' are not planed to be implemented.

'Select' block will simply be ignored.

'Text Description' block will be displayed on the screen during the
conversion, or will be ignored, depending of settings.

'Message block' depending of settings can be ignored, displayed on the screen
during the conversion, or converted into 'Character array' block which may be
seen in Tape Manager in the emulator itself.

'Archive Info' block is ignored.

'Hardware Info' block in {Start button:sbutton} checks whether the program
uses 128 K features, and in that case switch to SPEC128.EXE , if the program
uses Timex 2068 features, active emulator will be TS2068.EXE, if the computer
is not supported the conversion will fail, and if the peripheral is not
supported, it will be ignored.

'Emulation Info' sets border and video synchronization, if the conversion is
started via Start button.

'Custom Info' block is ignored.

'Snapshot' block is extracted only in Start button. Only Z80 snapshots are
supported. If there are more than one snapshot blocks, the last one will be
executed.

'Z' block is ignored.

TZX format is very complex, so this conversion is a bit slower than other
conversions.

.topic tzxsetup
 ษออออออออออออออออออออออป
 บ TZX CONVERSION SETUP บ
 ศออออออออออออออออออออออผ

This option opens a huge {dialog} with 15 {checkboxes:chkbox},
{OK button:okbutton}, and {Cancel button:cancelbutton}. Using this option you
may customise treatment of {TZX files:waratzx} in the emulator. Each checkbox
will be described separately.

Sample standard blocks rather than copy them:

Determines whether 'Standard speed' {blocks} would be converted into
{EAR Sample:earsample} or {Headerless} blocks. First variant is a bit more
reliable, because it will work in all cases, but it will cause remarkable
slower loading even with quite ordinary programs.

Sample pause after standard block:

Determines whether pause after 'Standard speed' block would be sampled, or
ignored.

Sample Turbo blocks rather than copy them:

Determines whether 'Turbo loading' blocks would be converted into EAR Sample
or Headerless blocks. First variant is more reliable. Second variant (if
EDGE RECOGNIZER success to recognize block) will cause remarkable faster
loading, but first variant will work in all cases.

Sample pause after turbo block and pure data:

Determines whether pause after 'Turbo loading' and 'Pure data' blocks would
be sampled, or ignored.

Sample pure tone and sequence of pulses:

Determines whether 'Pure tone' and 'Sequence of pulses' blocks would be    
sampled or ignored; second variant is necessary if you determine that 'Pure
data' blocks would be converted into Headerless blocks.

Sample pure data rather than copy them:

Determines whether 'Pure data' blocks would be converted into EAR Sample or
Headerless blocks. Like in previous similar options, first variant is much
more reliable.

Embed messages in converted tape:

When this option is switched on, 'Message' blocks will be converted into
'Character array' {header} blocks, which may be seen in Tape Manager into the
{emulator:runemul} itself. The message will be truncated to 10 characters.
This option is useful for separating levels in games supported in
{TZX format:waratzx}.

Convert direct recording:

Determines whether 'Direct recording' blocks would be converted or ignored.

Put all blocks and groups in separate samples:

When this option is turned off, during conversion logical structure of TZX
file will not be preserved, so converted file will have "pasted" blocks.
Converted file then will have much less blocks, and the drawback is a fact
that blocks on converted tape will not logically correspond to blocks on TZX
file. Switching this option off may drastically speed up conversion of TZX
files which have a huge number of blocks (for example, in Firebird Bleepload
programs).
  
Allow negative jumps (not yet implemented):

Determines would negative jumps in TZX file would be allowed (although they 
are not implemented yet).
  
Show text description blocks:

Determines whether text descriptions from 'Text Description' block would be  
displayed on the screen during conversion or would be ignored.

Show message blocks:

Determines whether 'Message' blocks would be displayed on the screen during
conversion, or would be ignored.

Extract snapshot block

Determines whether 'Snapshot' block would be extracted into a
{snapshot:snapfiles} file during starting of TZX files using
{'Start' button:sbutton}, or would be ignored.

Show warning for nonimplemented blocks:

Determines whether the environment would display warning message for
nonimplemented TZX blocks.

Consider hardware and emulation info:

Determines whether 'Hardware Info' and 'Emulation Info' blocks would be
considerated during starting of TZX files using 'Start' button, or would be
ignored.

.topic blocks
 ษอออออออป
 บ BLOCK บ
 ศอออออออผ

Block in {tape file:tapefiles} is equivalent to block on real tape.

On real tape, block contains leader (you can usually see red-cyan lines, and
hear continuos tone) and data part (usually lines are yellow-blue and tone is
variable). In data part there are synchro byte, {flag byte:flagbyte}, actual
data and check byte.

On emulated tape (tape file) we store flag byte and actual data. In native
Warajevo format check byte is calculated, so it is always good. In Lunter's
TAP format, check byte is stored too.

Block can be {header}, {headerless} and {EAR sample:earsample}.

.topic header
 ษออออออออป
 บ HEADER บ
 ศออออออออผ

Header is a special {block:blocks} that define size, name and type of data in
following {headerless} block.

Header is always 17 bytes long.

In {listboxes:listbox} we used some abbreviations to display different headers:

 PENETRATOR run 10, 1200+30

This is basic program called PENETRATOR. It is long 1200 bytes without
variables, and variables require additional 30 bytes. The start line is 10.

 TLL       bas  180+0

This is basic program called TLL. It is long 180 bytes without variables, and
variables not require additional space. The program has no autostart.

 ACCOUNT   num a(), 5000

This is numerical array, original name is a(). It is 5000 bytes long.

 TELEPHONE chr a$(), 12123

This is character array, original name is a$(). It is 12123 bytes long.

 MEMORY    byt 32000, 3121

This is memory image. The starting address is 32000, size is 3121 bytes.

.topic headerless
 ษออออออออออออป
 บ HEADERLESS บ
 ศออออออออออออผ

Headerless can be in two types, {compressed:implode} and uncompressed.

In {listboxes:listbox} we used some abbreviations to display different
headerless {blocks}:

 Headerless len 20000 F:255

This means that block is 20000 bytes long and {flag byte:flagbyte} is 255.

 Compressed len 2048 (510)

This means that the block is compressed, original size was 2048, but it use on
disk only 510 bytes.

.topic earsample
 ษออออออออออออป
 บ EAR SAMPLE บ
 ศออออออออออออผ

{Warajevo:abzxtools} emulator also supports special {blocks} which contain
samples of real tape input which are taken in regular time intervals. These
samples usually represent samples of tone record of a some totally
nonstandard-saved program, but principally, they may also represent music or
speech records, etc.

Blocks which contain samples may be {compressed:implode} or uncompressed.

In {listboxes:listbox} we used some abrevations to display blocks which
contain samples:

 EAR sample len 64993 (5807)

This is a block which contains pure samples from tape EAR socket. Logical
length of the block is 64993 bytes, but it on the disc ocuppies only 5807 bytes
due to compression.

Sampled tone records may be very long (500 KB or more). Due to technical
reasons, Warajevo emulator cuts these records in a serial of no more than 64
KB long blocks. So, one sampled record may be splited to ten or more blocks.

.topic flagbyte

Flag byte is byte that determine type of {block:blocks} ({header},

is usualy 0 for headers or 255 for data blocks following header.

Some headerlesses can have different value.

in Z80 snapshot file, and the overlays in Warajevo {TAP file:tapefiles}.

number 5 will be stored in TAP file as a fifth block. If the SLT file contains
overlays in non-sequencial order, the fictive blocks will be created.

When you select this option, you will see {file selection dialogs:fsdialog}
to choose SLT file name.

After you selected SLT file to be converted, the another file selection dialog
will prompt you to select output snapshot file (in Warajevo compatible Z80
format), and the third one that will ask you for the name of the tape file.

.topic snaptap
 ษออออออออออออออออออป
 บ SNAPSHOT TO TAPE บ
 ศออออออออออออออออออผ

This option converts active {snapshot file:snapfiles} to {tape file:tapefiles}.

This conversion requires small loader, it is initially put in video memory.
If you can find better place in memory, modify values in two
{input lines:inputline} named 'Startup Routine address' and 'Startup Register
Stack address'.

Startup routine is 32 bytes long and Startup register stack is 32 or 34 bytes.
Be careful, avoid zone 23296-24999 for 48 K loaders and 23296-24999 and
49152-65535 for 128 K loaders, because it is likely that your startup routine
will be overwriten.

If you can not find other place in memory, consider further destiny of this
TAP file. If you want to use it only on {Warajevo:abzxtools} or transfer it
to original Spectrum, select the first radio button. In this case, the routine
and stack will use only two bottom lines of the screen.

If you want to convert the tape file to Z80 emulator, or any other emulator
that has trap for headerless ad lower address than Warajevo (for example 1366)
select the second radio button. The screen damage will be in two bottom lines
of the screen and in eight from the bottom.

If you want to convert to emulator that supports only loading from Basic (ex.
Irish, Polish), select the third radio button. In this case, the topmost third
of the screen will be damaged including bottommost two lines.

If you choose 4th, 5th or 6th radio button, this tape file will not be
directly usable, but you can copy its contents to MDR file or real microdrive,
Opus Discovery diskettes, Disciple diskettes or Wafadrive (currently there
is no emulator for PC that emulates Wafadrive or Opus, while only Z80 emulates
Disciple).

If you choose 7th radio button, this tape file also will not be directly
usable, but you can convert it to {TRD format:trdwara} (TR-DOS disk emulation
format). TAP file, which is produced using this conversion, may be directly
converted into TRD format without any manual modification of BASIC loader.

After you press {OK button:okbutton}, you must select output tape file name
using {file selection dialog:fsdialog}. This conversion does not support
conversion of Timex snapshots yet.

View the contents of the current {cartridge file:TapeFiles} as a logical list

option from {Sectors:mdvsectors} submenu. Sometimes it will not be enough. In
such case, only {format:mdvformat} or {editing:mdvsedit} whole sector area will
help.

about sectors of the cartridge file and the {OK button:OKbutton}.

.topic izvjbase
 ษอออออออออออออออออป
 บ DATABASE REPORT บ
 ศอออออออออออออออออผ

This option will create report of the files in the {data base:database}, which
may be printed on printer, screen and to the disk file. The {dialog} for this
option consists one group of {checkboxes:chkbox}, three group of
{radio buttons:radiobutton}, three {input lines:inputline},
{OK button:okbutton} and {Cancel button:cancelbutton}.

Using checkboxes you can select which {fields:editbase} will be included in the
report. In the report each record will be printed in the new line. If you
select too many fields in the report, some fields may be cutted (due to limited
paper width) but optimally. If you include {Problems:fproblems} field in the
report, problems will be printed as the coded string. Characters in the string
have following meaning:

 F - Flickering
 S - Too slow on Herc/CGA/EGAMono
 V - Too slow on EGA/VGA
 H - Bad Herc/CGA/EGAMono shades
 N - Sound not recognizable
 I - Hangs up or resets without /I
 R - Hangs up or resets even with /I
 L - If hangs, can not help F9, F10
 B - Border flickers too much
 T - Tape emulation problems
 A - Interface emulation problems
 M - Exits with message
 O - Problem not listed here
 ! - Can't work even theoretically

Input lines 'Paper length' and 'Printable lines' should contain paper length in
lines (default 72) and the number of effectively printed lines on the paper
(default 66). Line 'Report width' should contain number of characters in one
row.

Using one group of radio buttons you can select output device (if you select
screen, you can {browse:scrreport} through report {window} on the screen).
Using second group you can select do you want printing all records, only
{marked:markbase} records or only unmarked records. Third group, named 'Printer
type' selects type of the printer. It selects, in fact, necessary control
codes, and maximal usable report width. If you select ASCII printer, control
codes will not be sent. Maximal usable report widths in characters are:

  80 for ASCII A4

.topic runemul
 ษออออออออออออออป
 บ RUN EMULATOR บ
 ศออออออออออออออผ

Pressing F10, click to Emulator field into bottommost screen line, or double
click to Screen window (if the environment is in graphic mode) will run the
emulator kernel. If no {snapshot files:SnapFiles} is selected, a 'pure'
emulator (with empty memory image) will be executed, e.g. you will see after a
bit time known copyright message:

 (C) 1982 Sinclair Research Ltd

In this case, 48K version of the emulator will be loaded by default. You can
change this default using option {Emulator:emulsel} into {Setup} menu.

If a snapshot file is selected, this file will be immediately loaded into the
emulator after executing, so selected snapshot file will be run. Emulator type
(48K, 128K or Timex) will be determined from {snapshot's header:sinfo}. Main
file {window} always display which emulator file will be used.

All selected {setup parameters:setup} will be passed into the emulator.

After entering to the emulator kernel, you may use following function keys:

.topic cartfiles
 ษออออออออออออออออออออออออออออป
 บ MICRODRIVE CARTRIDGE FILES บ
 ศออออออออออออออออออออออออออออผ

Cartridge files are used for emulation of cartridge tape in real {microdrive}.

If cartridge file length is not divisible by 543, extra bytes will be ignored.

.topic talgs
 ษออออออออออออออออออออออป
 บ TAPE LOADING METHODS บ
 ศออออออออออออออออออออออผ

You have three algorythm for emulation of a real tapes using a
{tape files:TapeFiles}. Default algorithm is AUTO, you can select SLOW or FAST
for some special purposes. For more details see the manual.

 FAST
 ----

In this mode emulator will recognize only programs which use original loading
routine from the ROM. Loading will always be very fast, but programs with
non-standard loading routines will not work.

 SLOW
 ----

In this mode emulator will recognize many programs which use non-standard
loading methods, but loading is like on real Spectrum (but slightly faster,
depending of computer speed). Normally saved programs will be treated on same
way, so loading will be always slow.

 AUTO
 ----

In this mode emulator tries to determine would the program use standard ROM
loading routine (in such case loading will be fast), or non-standard routine
(in such case loading will be slow). This is default and recommended method.

.topic baudrate
 ษออออออออออออป
 บ BAUD RATES บ
 ศออออออออออออผ

Baud rate determines effective speed while transferring programs using
{cassette interface:commcinf} or {RS232 interface:commrs232}. Roughly spoken,
one baud (1 Bd) is equal to one bit per second (1 bit/s or 1 Bps).

With cassette transfer, baud rates can be defined only as average value,
because tape signal is frequency modulated (FM). More precisely, this is
digital frequency shift keying (FSK) signal if you are expert for
telecomunications. Default average baud rate is 1500 Bd (2000 Bd for zero bits
and 1000 Bd for one bits), which means about 11 KB per minute in average.

When you transfer normally saved (unprotected) programs, keep this baud rate to
1500 Bd. Eventually, if your cassette player don't work so good, and you have
loading problems, try about 1400 Bd if your casette player is too slow, or
about 1600 Bd if it is too fast.

There are also many protected programs (known as speedlock programs) which use
non-standard tape loading routines with higher baud rate. This baud rate is
usually from 2000 to 3000 Bd, rarely higher. To transfer such programs you must
firstly determine baud rate by experimenting. Start from higher to lower baud
rates. For example, start with 3500 Bd, then successively decrease baud rate in
about 100 Bd increments (e.g. 3400, 3300 etd.) until you load protected block
correctly. This will always help if loader is not totally non-standard (e.g.
with variable baud rate like in original 'Skool daze' or with more sync pulses
like in 'Robocop'). In this case, you must use option
{Sample from cassette:casssample}.

If you are hacker or if you have knowledge about machine language, you can try
to read protected loader using our internal monitor, and instead of determining
baud rate, you can directly read time constants from the loader and set them
using {Advanced cassette settings:advcassetting} option. This is the best
method, and finding time constants is not a hard job using our monitor. Read
the manual for details.

With RS232 transfer supported baud rates are 110, 150, 300, 600, 1200, 2400,
4800 and 9600 Bd. Default is 9600 Bd which means about 70 KB per minute.
Transfer is very reliable, so change this only if you have problems during
transfering.

.topic sectors
 ษอออออออออป
 บ SECTORS บ
 ศอออออออออผ

Sectors are records on a {cartridge file:cartfiles} which are used to emulate
real sectors on real cartridge file. One sector is 543 byte long.

On real {microdrive}, one sector has two parts: {sector header:sheader}, and
{sector block:sblock}. Between header and block, and also between two sectors
there is a little {gap}.

Emulated sector has following format:

   1 byte header flag (always 1)
   1 byte sector number
   2 bytes unused
  10 bytes cartridge name
   1 byte header check sum
   1 byte {block flag:bflag}
   1 byte {record number:recnum}
   2 byte {record length:reclen}
  10 byte file name
   1 byte descriptor check sum
 255 bytes actual data
   1 byte actual data check sum

Using {View:mdvview} option in {Microdrives submenu:microsub} you can view
system informations about each sector on the cartridge.

.topic sheader
 ษอออออออออออออออป
 บ SECTOR HEADER บ
 ศอออออออออออออออผ

Header of the {sector:sectors} is only a signature that mark beginning of each
sector on real cartridge tape. The format of a header is:

 12 bytes of lead-in signal
  1 byte header flag (always 1)
  1 byte sector number
  2 bytes unused
 10 bytes cartridge name
  1 byte check sum (using modulo 255)

Lead-in signal (10 zeros and two #FF's) on real microdrive has only
synchronising purpose, so we do not put it in a {cartridge file:cartfiles}.
So, our header is 15 bytes long, not 27 bytes.

.topic sblock
 ษออออออออออออออป
 บ SECTOR BLOCK บ
 ศออออออออออออออผ

Block of the {sector:sectors} contains actual data. The first part of the block
contains block descriptor, which structure is similar like
{sector header:sheader}:

 12 butes of lead-in signal
  1 byte {block flag:bflag}
  1 byte {record number:recnum}
  2 byte {record length:reclen}
 10 byte file name
  1 byte check sum (using modulo 255)

After this, follows 512 bytes of actual data, and actual data checksum using
modulo 255 too (not 256)!

Lead-in signal (10 zeros and two #FF's) on real microdrive has only
synchronizing purpose, so we do not put it in a {cartridge file:cartfiles}.
So, our block is 528 bytes long, not 540 bytes.

First 9 bytes of actual data in zero record of non-PRINT
{logical file:logfiles} contain additional informations about file such a type
(BASIC, CODE, DATA), start address of loading, etc. See manual for detail
description.

.topic bflag
 ษออออออออออออป
 บ BLOCK FLAG บ
 ศออออออออออออผ

In a block flag bit b0 is always 0 to say that this is a {sector block:sblock},
not a {sector header:sheader}. Of course, this is important only at real
cartridge tape.

Bit b1 is one if this block is EOF block, e.g. last block which belongs to one
{logical file:logfiles}. If block is not a EOF block, {record length:reclen}
must be 512.

Bit b2 is one if this block belongs a non-PRINT file, e.g. file created using
SAVE* command.

Bits b3-b7 are always zero (not used).

.topic recnum
 ษอออออออออออออออป
 บ RECORD NUMBER บ
 ศอออออออออออออออผ

Each {logical file:logfiles} can occupy more than one {sector:sectors} (sectors
contain only 512 bytes of actual data). So, logical file must be divided to 512
byte long records. Field record number contains logical record number, starting
from zero. Last record is EOF record, so it must has b1=1 in a
{block flag:bflag}.

If record is not a EOF record, {record length:reclen} must be 512.

First 9 bytes in zero record of a non-PRINT file contains
{additional informations:sblock} about file.

.topic reclen
 ษอออออออออออออออป
 บ RECORD LENGTH บ
 ศอออออออออออออออผ

Record length contains actual length of data in a {record:recnum} of one
{logical file:logfiles}. If record is not a EOF record, record length must be
512.

Unallocated and bad blocks both have zero record length. Unallocated blocks
have {EOF bit:bflag} equal zero, but bad blocks have EOF bit equal one.

.topic gap
 ษอออออป
 บ GAP บ
 ศอออออผ

Gap is a piece on a real cartridge tape with no data on it (nor zeros nor
ones). {Unformated:mdvformat} cartridge has only gaps.

In {Warajevo emulator:abzxtools} each {sector:sectors} with wrong header
checksum will be treated as gap. This is not enough for correct emulation,
because there must be some gaps between sectors and between
{sector header:sheader} and {sector block:sblock}. So, emulator inserts some
dummy gaps at appropriate places when ZX software tries to read ZX Interface 1
status register (IN 239).

Logical structure of a sector can be adjusted using {Verify:mdvsverify} option
in {Sectors submenu:mdvsectors}.

.topic logfiles
 ษอออออออออออออออป
 บ LOGICAL FILES บ
 ศอออออออออออออออผ

On a real cartridge tape, you can put many files on it. But we emulated
cartridge tape using only one {cartridge file:cartfiles}. So, we can say that
one cartridge file may have many logical files on it. You can see list of a
logical files on cartridge using CAT command from BASIC, or using
{Catalog:mdvcat} option from {Microdrives:microsub} submenu.

Logical file can be PRINT file and non-PRINT file. PRINT files are files
created using PRINT# command in BASIC. Non-PRINT files are created using SAVE*
command.

Each {logical file:logfiles} can occupy more than one {sector:sectors} (sectors
contain only 512 bytes of actual data). So, logical files must be divided to
512 byte long {records:recnum}.

.topic vidtime
 ษออออออออออออออออออออป
 บ VIDEO DISPLAY TIME บ
 ศออออออออออออออออออออผ

Try changing of this parameter (in range 0-311) if some sprites on screen
flicker too much (for example, when you play some game).

This parametar determines relative delay between vertical screen retrace (which
is synchronized with Spectrum interrupt) and video updating. Default is 150,
which means 'update screen nearly in a middle time between two interrupts'.

.topic sbutton
 ษออออออออออออออป
 บ START BUTTON บ
 ศออออออออออออออผ

'Start' button is located in the bottom left corner of the screen, like
in Windows 95. It may be activated using mouse or using {Alt+S:hotkeys}. This
button makes easier {running:runemul} of Spectrum programs, not only programs
in {Warajevo:abzxtools} format ({TAP:tapefiles} or {Z80:snapshots}), but also
programs in formats of {other emulators:other} ({SNA:warajppm},
{BLK:spec200wara}, {SNP:warasnpm} etc.), and even programs which are archived
in ZIP archives.

After activating of the 'Start' button, a {file selection dialog:fsdialog}
will appear.

If you select a Warajevo file (TAP, Z80, MDR, DCK), it will be passed to the
emulator, and started (in case of TAP files a first program in the tape will
be started, in case of MDR files {program:logfiles} stored on the
{cartridge:cartfiles} with name "run" will be started, and in case of
{DCK files:dockfiles} DCK file will be loaded, but started only if DCK file
contains auto-boot programs like LROS or AROS programs).

If you select file which is not in Warajevo format (for example, SNA,
{SP:spwaram}, BLK, SNP, {TZX:tzxwara}, {LTP:garabikwara}, {SIT:warasitmm}
etc.), the environment will perform automatic conversion in Warajevo file
TEMP.Z80 or TEMP.TAP (depending on whether selected file is snapshot or tape
file), passes converted file to the emulator, and start it (all these things
will take very little time, practically immediately, except with very complex
formats, like TZX which may take slightly longer time).

If you select a file with extension .ZIP (archived file), the emulator
will create a temporary directory called ZIPRUN, erases it content if it was
previously created, and then, by calling program PKUNZIP.EXE (which must be
located in currently active path set using DOS command PATH) unpacks archive
in this directory. After unpacking, if the archive contains only one file,
then the emulator will deal with this file like in previous case. But, if the
archive contains more files, a new dialog appears which allows user to select
file which will be started (using previously described algorithm).

This is a list of formats currently supported by Start Button:
Z80, TAP (Lunter), TAP (Warajevo), BLK, SPC, LTP, TZX, ZXS (Museum),
ZXS (ZX32), ZXT (ZX32), VOC, SLT, SNA (48), SNA (128), SP (VGASPEC),
SP (Spec 0.99), PRG, SEM, SIT, SNP, SCR, MDR, DCK and ZIP.

.topic binlros
 ษออออออออออออออออป
 บ BINARY TO LROS บ
 ศออออออออออออออออผ

Using {file selection dialog:fsdialog} enter name of source
{binary file:dockconvert}, and destination {DCK file:dockfiles}.

emulator cartridge for Timex computer (Spectrum emulator which must be started

.topic mswindows

.topic dockfiles
 ษออออออออออออป
 บ DOCK FILES บ
 ศออออออออออออผ

{Warajevo emulator:abzxtools} introduces special DCK files which keep content
and configuration of additional Timex Sinclair 2068 memory banks (DOCK and
